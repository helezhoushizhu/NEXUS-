# 图像碎片重建思路

## 一、任务介绍

本次任务需要使用 Python 和 OpenCV，将顺序被打乱、方向可能发生旋转的图片碎片重新拼接，恢复出完整图像。

素材分为 A、B、C 三组：

| 素材 | 碎片数量 | 碎片尺寸 | 完整图像尺寸 |
| --- | --- | --- | --- |
| A | 961 张 | 64 × 64 | 1024 × 1024 |
| B | 961 张 | 64 × 64 | 1000 × 1000 |
| C | 868 张 | 64 × 64 | 1024 × 928 |

由于碎片的顺序已经打乱，不能通过文件顺序直接判断位置，需要根据图片内容寻找碎片之间的关系。

## 二、基本思路

题目中的相邻碎片通常存在 50% 的重叠区域。因为重叠部分来自原图的同一位置，所以在方向正确的情况下，两张图片的重叠区域应该具有相同的像素值。

例如，两张 64 × 64 的碎片在水平方向重叠 32 像素：

- 第一张图片的右半边；
- 第二张图片的左半边。

这两部分对应原图中的同一块区域。如果像素完全相同，就可以将第二张图片作为第一张右侧邻居的候选。

## 三、实现过程

### 1. 读取图片

根据选择的素材 A、B 或 C，找到对应文件夹下的所有 PNG 图片，并使用 OpenCV 的 `cv2.imread()` 读取。

读取后检查图片是否成功打开，以及尺寸是否为 64 × 64。

### 2. 处理旋转

每张碎片可能被旋转过。因此，对每张图片尝试四个方向：

- 原始方向；
- 顺时针旋转 90°；
- 旋转 180°；
- 顺时针旋转 270°。

通过比较不同方向下的重叠区域，寻找能够匹配的碎片。

### 3. 寻找相邻碎片

选择一张碎片作为起点，并把它的位置设为 `(0, 0)`。

依次寻找它上、下、左、右方向的候选碎片。通常相邻碎片之间移动 32 像素，但边缘位置可能存在不同的重叠宽度，因此还需要进行检查。

找到匹配的碎片后，记录：

- 碎片的编号；
- 碎片的位置；
- 碎片需要旋转的方向。

然后以新找到的碎片为基准，继续向外寻找，直到无法找到新的碎片。

### 4. 检查匹配关系

有些碎片可能包含纯色或重复图案，因此一处重叠区域相同，不一定能唯一确定它的位置。

为了减少错误，需要检查：

- 碎片是否与周围已放置的碎片一致；
- 同一位置是否存在多个候选；
- 碎片之间是否出现位置冲突。

### 5. 拼接完整图片

由于起点是任意选取的，某些碎片的坐标可能为负数。将所有坐标统一平移，使最小坐标变为 0，再创建画布并放入碎片。

图片放入画布的基本形式为：

```python
result[y:y+64, x:x+64] = image
```

其中，`(x, y)` 是碎片在画布上的位置。

### 6. 调整最终方向

由于起点碎片的方向不一定是原图的正确方向，拼接完成的整张图片也可能发生整体旋转。

根据本次结果的方向要求：

- 素材 A 的最终结果顺时针旋转 90°；
- 素材 B 的最终结果顺时针旋转 90°；
- 素材 C 的方向根据实际结果检查。

这一步旋转的是**整张拼接结果**，与前面旋转单张碎片不同。

### 7. 保存和检查结果

将结果分别保存为：

- `result_A.png`
- `result_B.png`
- `result_C.png`

保存后检查：

1. 是否所有碎片都已经放置；
2. 图像是否存在空白、错位或明显不连续的区域；
3. 重叠区域是否一致；
4. 图像尺寸是否符合要求；
5. 最终图片的方向是否正确。

## 四、总结

本题的核心是利用碎片之间的重叠区域寻找位置关系，再通过旋转、坐标记录和画布拼接恢复图像。

基本流程为：

```text
读取碎片 → 尝试旋转 → 查找重叠 → 记录位置 → 拼接图像 → 调整方向 → 保存检查
```

实际运行时，如果出现多个匹配候选或部分碎片无法放置，需要根据运行结果进一步调整程序。
